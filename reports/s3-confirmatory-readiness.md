# Study 3 confirmatory readiness review — reconstruction and verdict

**Date:** 2026-08-31. **Purpose:** establish, from the record rather than from memory, what the confirmatory experiment is; then decide whether the programme is ready to freeze and run it. ## 1. The confirmatory experiment, reconstructed from the record

Sources: `observer-zero-study-3-design-v0.4.md` (authoritative register; v0.1–v0.3 stand where not superseded), `s3-r40-generative-boundary.md` §§1–19, `s3-r38-positive-control.md`, `s3-r39-mundane-prior-ablation.md`, `s3-multifamily-licensed-probes.md`, and the code (`study3Pilot.ts`, `study3.ts`, `corpusFilter.ts`, `manifest.ts`).

- **Scientific question:** do autonomous scientist agents, given anomalous instrument data whose true explanation is external generation, revise toward external-generative accounts — measured against a matched in-world control?
- **Primary endpoint (R16 as amended by R34):** ΔL1 = P(L1 | W-D-exact) − P(L1 | M-D-high) **at final belief state**, where **L1 = summed external-generative class mass > 0.05** (max-single-hypothesis is a registered *sensitivity* analysis, not the primary). §1.1 leaves **ΔL1 vs ΔL2 as primary** explicitly open as Nick's construct decision, with ΔL1 recommended and the other second in a fixed sequence.
- **Secondaries:** ΔL2 (fixed-sequence, gated); **ever-L1** from the τ timeline (co-registered — the metric lesson from §19 was anticipated here); L3 family-conditional, never pooled; L3ᵃ exploratory (R37). Thresholds 0.02/0.10 and max-single as sensitivities.
- **Test:** exact conditional Mantel–Haenszel across family strata, one-sided, α = 0.05; asymptotic CMH sensitivity only; per-family Fisher descriptive.
- **Degenerate branch (pre-registered, §1.3):** assessed on the contrast cells only; if both arms empty in every stratum, the MH is reported as *degenerate* with an exact one-sided upper bound on Δ and a negligibility test at δ = 0.10, plus Jeffreys Beta-binomial posteriors. Given the pilot record (τ-based 1/57, R39 0/60), **this branch is the modal expected outcome and the design says so.**
- **Experimental unit:** the run (one agent-world-seed cell). **Worlds:** the 11-type roster; primary contrast W-D-exact vs M-D-high. **Seeds:** confirmatory range **2000–2099**, verified unspent today across every artifact on disk. **N:** 10/cell by cost (R41 registers the honest MDE: ≈12.5% one-sided with an empty control arm; ≈18–20% for 80% power — against a pilot upper bound of ≈6.6%).
- **Families (R19/R30):** roster Claude · sonar-pro · Mistral · Cerebras; **strata must be named at the freeze commit**, including the haiku-fallback-core question and a substitution rule (concrete for sonar: R28). Multi-family confirmation is therefore **pre-specified, not a new idea** — but the *specific* roster is a freeze-commit decision that was always reserved.
- **Health/exclusions:** R29 run-health gate; R38 fail-closed corpus-role separation (three-signal agreement or refusal); leak audit; R35 id-era rules.
- **Frozen vs open:** L1 threshold 0.05, level definitions, R8 opaque ids, R34 hierarchy, R35, degeneracy rule — frozen. §1.1, R19 strata, R37, R41 framing, R17 re-spec — open **by design**, to be closed in the freeze commit. Anything else changed now is a new DoF and must be disclosed as such.

## 2. RED — must be resolved before freeze

**RED-1 · The registered primary is not what the code computes.** `computeLevels` fires L1 on any single ext-gen hypothesis > 0.05; R16-as-amended registers **summed mass** > 0.05, with max-single as the sensitivity. Nobody caught this until this review. Mitigation already in hand: a mechanical sweep of all 132 eval-v4 sidecars found **zero snapshots** where summed would fire and max-single did not — no historical number moves. Required: implement summed-mass L1 (parameterised beside max-single), tier-0 test it through the full scoring path, re-run the pilot aggregations once to confirm the no-change result mechanically, and record the pre-freeze fix in the register.

**RED-2 · §1.1 — ΔL1 or ΔL2 as primary.** Reserved for Nick in the design. The recommendation on record (ΔL1 primary, ΔL2 second, fixed sequence) stands; what is not permitted is leaving it unstated.

**RED-3 · The scoring-procedure amendment (F32) is justified but not yet validated.** Per-item (solo) classification with majority-of-3 is *consistent with what v0.4 already registered* — the judge-discipline block requires "every item judged k ≥ 3 times with majority vote"; batching was an implementation shortcut, and F32 showed it is a deterministic, direction-biased defect at exactly the primary's boundary, with F15 as precedent. So the amendment needs disclosure, not apology. **But eval-v4's P3.4 validation (32/33, stable ×5) was run batched.** Before freeze, P3.4 must be re-run **solo** on the frozen v4 validation set, with the batched result reported beside it. If solo P3.4 degrades materially, that is a new fact and the freeze halts on it. (Expected cost: ~$2. Expected outcome: equal or better — F32's direction is batch-suppression — but expectation is not measurement.)

**RED-4 · R19 at the freeze commit: strata, roster, substitution.** Open questions that must be answered *in* the freeze document: (a) the named strata; (b) whether gemini joins — the R30 roster predates it, so adding it is a **disclosed post-R30 amendment** (defensible while confirmatory seeds are unspent; silently adding it because its licensed probe went well is exactly the adaptive selection the register forbids — if added, the disclosed reason must be key-availability and family coverage, decided before any confirmatory datum); (c) Mistral has only ever run under `mistral-large-latest`, which R19 rejects — a dated id must be pinned and smoke-tested, or Mistral drops with the substitution rule invoked; (d) **R28 deadline pressure: Perplexity retires `/chat/completions` on 27 Sept 2026 — 27 days away.** If sonar-pro is a stratum, its arm must complete before then, or the substitution rule fires. This is a scheduling constraint the freeze must state.

**RED-5 · Registered pre-freeze artefacts that do not yet exist.** (a) **R40(b), the frozen descriptive analysis plan** for the degenerate branch — assimilation-class taxonomy, named arm-wise comparisons, tests, multiplicity control, exact figures/tables. §16's three rules are components, not the plan. It must be written before freeze because the degenerate branch is the *expected* outcome. (b) **R37, L3ᵃ** — registered as "defined, built and validated before the freeze commit"; it was never built. Two legitimate closures: build it now under the registered circularity controls (days of work), or **register dropping it** with the limitation stated (defensible: it is exploratory, carries no claim, and the capability question it was invented to probe has since been answered by the licensed instrument-validation probes). Building it *after* confirmatory data exist is the one forbidden path. (c) **R17 re-specification** — the placebo-pair tripwire must be moved to a surface measurable under the expected outcome, pre-freeze, as v0.4 itself requires. (d) Small R14 judge-discipline items now load-bearing: the judge client does not record the API's *served* model per call (agent providers do; the judge should too — small code change); the calibration re-score at battery start/end needs its drift tolerance and action stated; the 20% second-judge (sonnet) cross-score needs a harness and a registered agreement statistic.

## 3. AMBER — disclose, do not block

- **F32b (paraphrase knife-edge) and F32c (disjunction handling):** documented judge-fragility findings. **No classifier change** — modifying eval-v4 to make them behave more intuitively would be exactly the untargeted prompt iteration the DoF register forbids, and solo scoring already recovers every consequential case found. They are disclosed limitations of any LLM-judged boundary and material for the judge-fragility leg of the paper.
- **The judge-blindness leakage test** (can the judge recover world type from its inputs?) is registered but never run; the input contract (label + rationale only) is blind to arm/seed by construction, but rationales necessarily carry world content. Run once, report, disclose.
- **Reconciled run ledger** (run id, family, world, seed, date, id era, health, included/excluded, corpus role): registered, not yet published. Mechanical; should accompany the freeze.
- **R41 framing:** with the pilot upper bound at ≈6.6% and the MDE at ≈12.5%, the honest registration is **precision/negligibility as the primary deliverable** (the degenerate branch's bound and δ = 0.10 test), with the MH as the test if the data surprise. State it; do not let the paper imply a powered hypothesis test.
- **Mock fixture single-instrument citation quirk:** tier-0 now uses a real reduced fixture, which satisfies the end-to-end need; the mock's quirk is cosmetic. Disclose in passing.
- **Prompt leak audit for the disposition arm:** the confirmatory battery runs prompt v0.1 exactly as frozen (R10) — R39 measured the neutral variant and the answer (0/60, zero formation) is now a *finding*, not a pending arm. The licensed variants live only in the instrument seed range 9190–9199 with three-signal fail-closed separation; parse-time hygiene refuses licensed variants on experimental seeds in both directions. Checked: `instrument-licensed`/`-forced` prompts never render into any experimental-variant path. GREEN in substance; listed here because the audit should be re-stated mechanically in the freeze doc (grep of rendered prompts for the forbidden-token list, which OZ-AUDIT-3 already runs).
- **Interpretation-rule asymmetry to pre-state:** the primary is final-state; ever-L1 is secondary. A transient-suspicion-then-assimilation outcome (the 9100-sonnet shape) scores 0 on the primary and positive on the secondary — the freeze doc must say in advance that this pattern is a *disposition-with-persistence-failure* reading, not a null and not a positive.
